# CLAUDE.md — контекст проекта для агента

## Что это за проект

Учебный проект магистратуры (AITU, курс «Artificial intelligence and machine learning»):
**многоагентная ИИ-система, которая генерирует недельное расписание университета**.
Входные данные — реальный Excel вуза `data/input.xlsx`: 13 программ, 270 групп, 105 аудиторий,
72 слота (Пн–Сб, 08:00–19:50). Проект сдаётся в три этапа, его оценивают по ТЗ (ниже).
Документацию и отчёты пиши на русском, код и комментарии — на английском.

## Обязательные требования ТЗ (не нарушать!)

- **≥ 4 агентов (цель: 5+), у каждого одна роль**, роли не дублируются. Сейчас 9 в конвейере + 3 в службе 24/7 (Intake, Watcher, Publisher) и её оркестратор Autopilot.
- **У агента не более 5 инструментов.** Это проверяется в `BaseAgent.add_tool`.
- **Ни один агент не делает > 40% вызовов LLM и инструментов** в типовом сценарии.
  Проверяется по `runs/<id>/events.jsonl` (сценарий S12). Добавляя вызовы, смотри на баланс.
- **Оркестратор только планирует и маршрутизирует**, предметную работу не делает.
- Агенты общаются **типизированными JSON-сообщениями** (`timetable/core/messages.py`).
  Большие объекты кладутся на blackboard (SQLite), в сообщениях передаются ключи и статусы.
- **≥ 2 внешних инструмента/источника**: Excel, OR-Tools CP-SAT, LLM Claude, SQLite, файлы.
- **Состояние задачи хранится явно** (`core/state.py`, `runs/<id>/state.sqlite`).
- **Лимиты шагов и времени, защита от зацикливания, ретраи, понятное сообщение при сбое.**
- **Логирование всех вызовов агентов, инструментов и LLM** (`core/runlog.py`).
- **Ключи API не хранятся в коде**: только `.env` (он в `.gitignore`).
- **Тестовые сценарии с ожидаемым результатом**: к Ассайнменту 4 ≥ 5, к экзамену ≥ 10. Сейчас их 19.
- В оценке экзамена 25% — «ответы на вопросы, понимание кода». Код должен оставаться простым
  и объяснимым: без лишних фреймворков и магии.

Этапы: **Ассайнмент 2** (5-я неделя) — архитектура, спецификация 4+ агентов, прототип.
**Ассайнмент 4** (10-я неделя) — рабочая система, логи, обработка ошибок, тесты.
**Экзамен** — демо, качество на 10+ сценариях, отчёт 5–10 страниц, презентация до 10 слайдов.

## Архитектура (кратко)

Оркестратор + blackboard. Пайплайн: `data.load_data → constraints.parse_constraints →
scheduler.plan_chunks → rooms.init_capacity →` для каждого куска `rooms.allocate_quota →
genetic.evolve (первая попытка) → scheduler.solve_chunk → validator.validate_chunk` (при неудаче `negotiator.resolve`, затем повтор) `→
rooms.assign_rooms → validator.validate_all ⇄ negotiator.repair → reporter.export`.

- ГА (`solver/evolve.py`, агент `genetic`): первое поколение расписания куска, лучшая особь → подсказка
  CP-SAT (`AddHint`). Связь с магистерской диссертацией автора (ГА для транспортных задач). `TT_GA=false` отключает.
- Модель: x[session, start_slot] в CP-SAT. Аудитории — счётные ресурсы на слот
  (ROOMS / K / CAP≥n / GYM). Конкретные аудитории назначаются после решения
  (`solver/rooms.py`).
- Декомпозиция: единицы «программа-курс» упакованы в куски по ~60 групп. Room agent выдаёт
  справедливые квоты остатка фонда.
- Validator — независимый чекер (`solver/checks.py`), он намеренно не использует код модели.
- LLM: `core/llm.py` (`LLMRouter`). Провайдер `TT_LLM=auto|openai|claude|offline`; `auto` берёт OpenAI,
  если задан `OPENAI_API_KEY` (модель `TT_OPENAI_MODEL`, по умолчанию `gpt-5-mini`, chat completions со
  strict JSON schema), иначе Claude (`TT_LLM_MODEL`, structured outputs), иначе офлайн-правила. При любой
  ошибке провайдера — офлайн-фолбэк, прогон не падает (сценарии S13 для Claude и S17 для OpenAI).

Подробно: `docs/ARCHITECTURE.md`, таблица агентов — `docs/AGENTS.md`.

## Команды (Windows, Python 3.12 venv)

```bash
.venv\Scripts\python -m pytest tests/test_units.py      # быстрые тесты, < 1 с
.venv\Scripts\python -m pytest                          # всё, включая 17 сценариев (~2–3 мин)
.venv\Scripts\python -m timetable.scenarios             # сценарии + обновить docs/scenario_results.md
.venv\Scripts\python -m timetable run --offline --programs IT --seconds 10   # быстрый прогон
.venv\Scripts\python -m timetable run --offline         # полный прогон всех 270 групп (~2.5 мин)
.venv\Scripts\python -m timetable agents                # таблица агентов из кода
.venv\Scripts\python -m timetable web [--port 8000]    # веб-платформа: http://127.0.0.1:8000 (+ служба 24/7)
.venv\Scripts\python -m timetable autopilot [--once]   # служба 24/7 без веба
```

Веб-слой ничего не знает об агентах: он вызывает `app.run(...)` в фоновом потоке и читает те же
файлы `runs/<id>/` (events.jsonl — живой журнал по байтовому смещению, state.sqlite — полные
payload сообщений и blackboard, timetable.csv, report.md). Отмена прогона — `RunContext.cancel`
(threading.Event), проверяется в `check_deadline`. Одновременно идёт один прогон (409 на второй).
Датасеты берутся из `data/`, `dataset-archive/`, `data/uploads/` и проверяются загрузчиком Data-агента.
Скриншоты для проверки UI: headless Chrome, `--screenshot` + `--virtual-time-budget`; адреса вкладок
`#/run/<id>/<tab>[/<mode>/<sel>]`, тема — `?theme=light|dark`.

Если `.venv` нет: `py -3.12 -m venv .venv && .venv\Scripts\python -m pip install -r requirements.txt`.
Результаты прогонов лежат в `runs/<имя>/`: timetable.html/xlsx/csv, report.md, events.jsonl,
state.sqlite, result.json.

## Правила работы

1. После любого изменения запускай `pytest tests/test_units.py`. После изменения агентов,
   решателя или ограничений запускай ещё `python -m timetable.scenarios`. Все сценарии должны быть зелёными.
2. Нашёл баг — сначала добавь сценарий или юнит-тест, который его ловит, потом чини.
3. Не ломай контракт сообщений и ключи blackboard без обновления всех агентов и `docs/AGENTS.md`.
4. Новый инструмент агента: проверь лимит 5 и баланс нагрузки. Новый агент: добавь в
   `app.AGENT_CLASSES`, `docs/AGENTS.md` и диаграмму в `docs/ARCHITECTURE.md`.
5. Метрики качества в документах и отчёте бери только из реальных прогонов. Не выдумывай числа.
6. Не коммить и не пушь без явной просьбы пользователя. `data/input.xlsx` — данные вуза: перед
   публикацией репозитория спроси, выкладывать ли их.
7. Ошибки хука `security_reminder_hook.py not found` идут от сломанного плагина, к проекту не относятся.

## Бэклог (по приоритету)

0. **no_room после ремонта**: на полном прогоне лекции иногда не хватает аудитории (Control Systems ST-2101/2102),
   Negotiator.repair не снимает. Публикатор такой прогон не публикует, служба повторяет — но лучше чинить причину.

1. **«Окна» у групп**: ~10 ч на группу в неделю на полном прогоне (на одной программе 2–3 ч).
   Варианты: больше времени решателю/ГА на кусок, веса окон в целевой функции, меметический локальный
   поиск ГА *после* CP-SAT (LNS по группам), более гибкие квоты.
2. Проверить режим с настоящим LLM (OpenAI: `OPENAI_API_KEY` в `.env`, `TT_LLM=auto`; или Claude):
   парсинг ограничений, выбор уступок, рецензия, резюме. Сравнить с офлайн-правилами на сценариях.
3. Точечное ослабление: `relax_user_constraints` сейчас смягчает **все** жёсткие запреты куска.
   Лучше смягчать только виновный (из диагноза ресурса и окна).
4. Преподаватели (в данных их нет): генератор нагрузки + ограничение AtMostOne на преподавателя.
5. Подгруппы для «Russian 1 / Kazakh 1» (две аудитории одновременно).
6. Материалы к сдаче: отчёт 5–10 страниц (IMRAD-стиль) и презентация до 10 слайдов на основе
   `docs/` и реальных метрик.
